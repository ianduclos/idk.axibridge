# Pen v2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the pen tool look and feel like a professional vector pen: constant-size round/square points, point join types, segment insert/bend, point delete with refit, continue/join, Space/Shift placement aids, a curvature-pen mode, sketch-then-fit, a knife, and (last, revertible) direct arm dragging.

**Architecture:** The server stays a flattener: `sources/pen.py` keeps Bézier anchors as the one stored geometry and gains two optional fields (`PenAnchor.join`, `PenSubpath.kind`) that it preserves but never draws from. All curve editing math lives in one new pure ES module, `static/js/pen_ops.js`; overlay rendering moves to `static/js/pen_overlay.js`; `pen.js` keeps gestures only. Curvature-mode subpaths store fully derived handles (recomputed in the browser after every edit), so old readers, tween morphs and the MCP see ordinary Bézier anchors. The one server-side algorithm is the curve fitter (`axibridge/curvefit.py` + `POST /api/geometry/fit`), which plan B also uses.

**Tech Stack:** Python 3 / FastAPI / Pydantic v2, numpy; vanilla ES modules built by Vite; pytest + Playwright (chromium) acceptance tests.

**Spec:** `docs/superpowers/specs/2026-10-22-pen-fill-hand-design.md` (part A and "Settled after the builder check").

## Global Constraints

- Existing pen layers in saved projects load and draw identically (anti-goal: "Any existing pen layer drawing differently after the change").
- Handles/points render at a constant screen size at every zoom; smooth/symmetric = round, corner = square. Colours stay as today (`--live`, `--rust`, `--bench`).
- `join` values exactly: `"corner"`, `"smooth"`, `"symmetric"`. `kind` values exactly: `"bezier"` (default), `"curvature"`.
- Angle snap step 15°. Curvature-pen arms are one third of the chord, tangent parallel to (next − prev).
- Every committed edit goes through `POST /api/layers/{id}/regenerate`; a drag is one coalesced undo step (`coalesce` key per layer + gesture), one ⌘Z per gesture.
- No emoji in UI; icons are inline Lucide SVG with `.tool-icon`.
- Edit sources in `axibridge/static/`; run `npm run build` before UI tests; `npm run typecheck` clean.
- Tests use temporary ports and `AXIBRIDGE_CONFIG_DIR` (existing fixtures do this). Never touch a server on port 2942.
- Out of scope: snapping to geometry (P6), numeric entry (E7), curvature comb, plot-order arrows, branching paths, smooth-spline/Hobby modes, cross-layer knife/join.

## Review Focus

3. Deleting points until a subpath has 1 or 0 anchors, and knifing a subpath into a piece with a single anchor — no crash, degenerate pieces dropped. Tests in Tasks 3 and 9.
4. Sketch-then-fit on a stroke with repeated/coincident points or fewer than 3 points — returns a valid anchor list (straight segment), never NaN. Test in Task 2.
5. Zoomed far in (≥ 800 %) and far out (≤ 25 %) — knobs stay the same screen size and remain hittable. Test in Task 4.

### Task 3: `pen_ops.js` — pure editing math

**Files:**
- Create: `axibridge/static/js/pen_ops.js`
- Test: `tests/test_pen_ops_ui.py` (imports the module in the page via `page.evaluate("async () => { const m = await import('/js/pen_ops.js'); ... }")` — check the served path of static JS with the existing `ui` fixture; with a built frontend use the source path the server also exposes, or run against `frontend_mode` source)

**Interfaces (all pure; anchors are `{x,y,in_handle,out_handle,join}` with handles as `[dx,dy]|null`; subpaths `{anchors, closed, kind}`):**
- `classifyJoin(anchor) -> "corner"|"smooth"|"symmetric"` — explicit `join` wins; else both handles present and collinear-opposite within 1e-6 rad → `symmetric` if lengths equal within 1e-6 mm else `smooth`; otherwise `corner`.
- `applyArmDrag(anchor, which: "in"|"out", vec: [dx,dy], breakJoin: boolean) -> anchor` — sets that arm; mirrors the other per `classifyJoin` (smooth: opposite angle, keep its length; symmetric: exact opposite; corner: untouched); `breakJoin` → returns `join: "corner"`.
- `splitSegment(subpath, segIndex, t) -> subpath` — de Casteljau; the drawn shape is unchanged; new anchor `join: "smooth"`.
- `nearestOnSubpath(subpath, x, y) -> {segIndex, t, dist}`.
- `bendSegment(subpath, segIndex, t, target: [x,y]) -> subpath` — moves the curve point at `t` to `target` by adjusting only that segment's two inner control points (least-change solution), then re-mirrors neighbours per their joins.
- `curvatureHandles(subpath) -> subpath` — for `kind:"curvature"`: every non-corner anchor gets tangent ∥ (next − prev), arms = chord/3 each side; corners and open ends get arms pointing a third of the way along their own chord(s); `join` of smooth points set to `"smooth"`.
- `deleteAnchor(subpath, i) -> subpath` — removes anchor i and refits the merged segment: sample the old two segments (64 samples), least-squares the new segment's inner controls keeping the outer arms' directions; a subpath left with < 2 anchors is returned with `anchors.length` as-is and the caller drops it.
- `snapAngle(dx, dy, stepDeg = 15) -> [dx, dy]` — same length, angle rounded to the step.
- `knife(subpath, a: [x,y], b: [x,y]) -> subpath[]` — splits at every crossing of segment a–b (each crossing becomes a shared end point), open results; pieces with < 2 anchors dropped; a closed subpath with ≥ 1 crossing opens there.
- `joinEnds(subpath, otherEnd: "start"|"end", subpath2, end2) -> subpath` — merges two open subpaths into one (the meeting anchors become one `corner` anchor at their midpoint).

- [ ] **Step 1: Write failing tests** — one per function, asserting with numbers, e.g. `splitSegment` of a known cubic at t=0.3: flatten before/after with a JS sampler in the test and max deviation < 1e-9; `classifyJoin` on four fixtures (no handles → corner; opposite equal → symmetric; opposite unequal → smooth; bent → corner); `applyArmDrag` symmetric mirror exact; `snapAngle(10, 3)` → angle 15°, length √109; `knife` on a straight 2-anchor subpath crossed once → 2 subpaths sharing the crossing point; `knife` crossing a closed square twice → 2 open pieces; `deleteAnchor` on a 2-anchor subpath → 1 anchor (caller drops); `deleteAnchor` of the middle of 3 anchors sampled on one circle arc → max deviation from the original < 1 mm; `curvatureHandles` on 3 points → middle tangent ∥ (p2 − p0), arm length = chord/3.

### Task 5: Editing gestures — insert, corner⇄smooth, bend, join switch, delete, continue/join

**Files:** Modify `axibridge/static/js/pen.js`, `axibridge/static/js/pen_overlay.js` (selected-anchor ring), `axibridge/static/index.html` (tool tips only); Test `tests/test_pen_v2_ui.py`.

**Interfaces:** Consumes Task 3 functions. Gestures (pen tool active, layer selected, nothing pending):
- **E1** click on a segment (within `HIT_PX`, not on a knob) → `splitSegment` at the nearest t.
- **E2** double-click an anchor → corner ⇄ smooth (to smooth: arms from `curvatureHandles`' rule for that one anchor).
- **E3** drag on a segment (moved > `DRAG_PX`) → `bendSegment`, live, one coalesced step (`coalesce: ["pen-bend", layerId]`).
- **E4** click an anchor selects it (ring); key `J` cycles its join corner → smooth → symmetric (re-mirroring the arms to match); the glyph shows the state.
- **E5** `Backspace`/`Delete` with an anchor selected → `deleteAnchor`; a subpath left with < 2 anchors is removed; a layer left with no subpaths stays as an empty pen layer.
- **E6** clicking the end anchor of an open subpath (nothing pending) starts continuing it: new clicks append to that end (prepend when it is the start) and commit back into the same subpath; clicking another open subpath's end while continuing joins them with `joinEnds`.
- Every committed edit: one `regenerate` call; E1/E2/E4/E5 are one undo step each.
