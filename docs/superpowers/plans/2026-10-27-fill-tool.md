# Fill tool implementation plan

> **For agentic workers:** Use superpowers:executing-plans for native execution, or superpowers:subagent-driven-development if Ian chooses delegation. Complete tasks in order, with failing tests before implementation.

**Goal:** Click an enclosed area of visible lines to create an editable, frozen pen shape, then optionally apply an existing fill effect.

**Architecture:** A pure geometry helper nodes resolved linework, polygonizes its faces and fits the selected boundary using `curvefit.fit_bezier`. Session methods supply the live resolved geometry and commit one ordinary pen layer. A canvas tool previews the candidate face and offers gap tolerance, Detail, fill style and outline controls.

**Tech stack:** Existing Python/Shapely/Pydantic backend and vanilla ES modules; existing Playwright acceptance harness. No new dependencies.

**Spec:** `docs/superpowers/specs/2026-10-22-pen-fill-hand-design.md`, part B and Settled 2.

## Global constraints

- Preview and plotting use the single `session.resolved*()` → `compose.resolve_project()` path.
- The fill is a snapshot, stored as ordinary `pen` generator parameters; holes are separate closed, filled subpaths.
- Clicking makes the shape; applying a fill is a subsequent explicit choice. Default: no fill effect, outline drawn.
- Numeric inputs are finite and bounded; each project mutation checkpoints once under the session lock.
- Reuse the curve fitter. Detail re-fits only the latest result, using transient raw rings; leaving that editing run discards them.
- Preserve existing pen geometry, undo, placement and source-only frontend behavior. UI uses Lucide SVG and existing palette tokens.
- API additions are documented for MCP in the same change. No machine motion is involved.
- Mac runs the app; Pi receives resolved plot jobs. No Pi app deployment or clone sync.
- Drag-to-union, subtraction and live source-linked fills remain deferred.

## Review focus

1. Several visible layers, moved/nested groups and effect/occlusion output must produce the face seen on screen.
2. A narrow hole or neighbouring face must survive fitting and gap repair; topology failure must be reported rather than silently accepted.
3. Timeline scrubbing or an edit during a request must not commit a stale candidate.
4. Dense generator output must cancel obsolete previews and report limits without silently simplifying or hanging the UI.
5. Failed writes, Escape and a mode switch during an asynchronous request must preserve a committed result without creating duplicates or reviving abandoned previews.

## Task 1: Pick a face from line geometry

**Files:** Create `axibridge/fill_geometry.py`, `tests/test_fill_geometry.py`.

**Interfaces:** `find_face(paths, point, gap_mm) -> Polygon | None`; `fit_face(face, detail) -> list[dict]` (closed Bézier `PenSubpath` dictionaries).

- [ ] Write tests for a square assembled from open lines, crossing lines forming adjacent faces, a nested island, duplicate lines, dangling strokes, exterior clicks and clicks on a boundary. Boundary clicks return no face with an explicit explanation at the API boundary.
- [ ] Add gap tests: 0 means exact geometry; an endpoint within tolerance may bridge to another endpoint or a segment; a larger gap stays open. A nearby unrelated face and a narrow hole remain distinct.
- [ ] Add fitted topology tests for sharp corners, concavity and a small hole: flattened rings remain valid and retain the clicked face and its holes. A failed fit is refused with guidance to raise Detail.
- [ ] Run `.venv/bin/python -m pytest tests/test_fill_geometry.py -q` and observe expected missing-helper failures.
- [ ] Implement union/noding and polygonization, selecting the smallest face strictly containing the click. Repair only dangling endpoints with explicit short connector segments; deterministic nearest candidate within tolerance, no whole-drawing buffering or grid snapping. Return closure and hole rings through the shared fitter. Validate the fitted polygon against its intended topology.
- [ ] Add explicit geometry workload bounds and cancellation checkpoints; pin reported-limit behavior with a test. Exact bounds are implementation limits, documented alongside the helper.
- [ ] Run the geometry tests; commit the verified helper and tests.

## Task 2: Resolve, preview and commit atomically

**Files:** Modify `axibridge/session.py`, `axibridge/api.py`, `docs/MCP.md`; create `tests/test_fill_api.py`.

**Interfaces:** `POST /api/geometry/face` accepts `{point: [x,y], gap_mm, detail, master_t}` and returns `{revision, rings, subpaths}`; `POST /api/layers/fill` accepts the same fields plus `revision`, and returns the new layer. Empty/unbounded/ambiguous picks return a clear 422; stale revision returns 409 without mutation.

**Parameter bounds (lead defaults):** coordinates use existing `FitCoord`; `gap_mm` 0–5 mm, default 0; `detail` 0–1, default 1; optional `master_t` 0–1. All finite. Preview does not checkpoint. The click uses exactly the same point/options/time as the displayed candidate.

- [ ] Write API/session tests for transformed groups, hidden layers, effect-shaped boundaries, occlusion and a nonzero timeline time, comparing the candidate to `session.resolved(master_t=...)`.
- [ ] Test stale commit, no-face pick and invalid input leave project/revision/undo untouched. Test successful creation is one undo step, uses identity paper-space placement, preserves hole subpaths, freezes against later source edits, and survives save/load.
- [ ] Run `.venv/bin/python -m pytest tests/test_fill_api.py -q` and observe missing-endpoint failures.
- [ ] Add session preview/commit methods. Resolve and select with the session's lock; commit checks the supplied revision, recomputes the selected face, validates the ordinary pen source and checkpoints once before inserting it. Reuse normal generation/caching conventions without invoking a second checkpoint or automatic centering.
- [ ] Add bounded API models/routes and normal project-change notification behavior. Document the endpoints as available through MCP `call_api`; no dedicated tool until routine use justifies it.
- [ ] Run the API tests plus `tests/test_curvefit.py`, `tests/test_pen_source.py` and `tests/test_mcp_freshness.py`; commit.

## Task 3: Canvas fill tool and editable result

**Files:** Create `axibridge/static/js/fill.js`, `tests/test_fill_tool_ui.py`; modify `axibridge/static/js/main.js`, `axibridge/static/index.html`, `axibridge/static/style.css` as required by the existing tool broker.

**Interfaces:** `initFillMode()`, `activateFillMode()`, `deactivateFillMode()`, `handleFillEscape()`. The module owns cancellable hover requests, latest candidate and latest-result refit state. Ordinary layer/effect APIs own all saved edits.

- [ ] Add acceptance tests for preview then click, selected editable pen result, no automatic fill, hole preservation and one-step creation undo.
- [ ] Add tests for zoomed/rotated coordinates; gap tolerance; live Detail refit followed by undo; stale preview; double-click/pending write; Escape/mode switch; failed create/refit retry. Disable the tool in sheet/tray previews like existing drawing tools.
- [ ] Add tests for choosing Hatch / Offset / Offset v2 / Cymatic after creation and toggling their existing `outline` parameter. "None" keeps the new boundary; disable outline-off until a fill effect is selected. Later tuning uses ordinary effect controls.
- [ ] Run `.venv/bin/python -m pytest tests/test_fill_tool_ui.py -q` and observe the missing-tool failures.
- [ ] Implement the broker entry, Lucide icon and companion controls. Hover highlights only the current face with even-odd holes; clicking commits that candidate. Block stale/abandoned request responses and concurrent writes. A gap repair is visible in the preview before it can be committed.
- [ ] Keep the fill companion controls available for the latest result while the tool is active. Detail changes re-fit all stored raw rings together, validate topology and regenerate with one coalescing token per slider gesture. Any unrelated edit, undo, selection change or tool exit ends refit ownership. Failed refits retain the previous geometry.
- [ ] Run the UI tests in source and built modes, plus existing drawing-tool completion and pen UI regression tests. Run typecheck/build; commit.
